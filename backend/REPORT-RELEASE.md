# 月报第一版：已确认发布

## 范围

管理员选择学生及月份，读取实际记录，编辑并保存中文（400字）和英文（800字符）评语，查看已保存月份，直接下载一页A4双语PDF。无Logo，无AI分析或自动评语翻译。

家长PDF只包含中英双语报告标题、学习数据、值得肯定的表现、进步重点与建议、双语教师评语。统计口径、内部状态及管理操作仅显示在管理员页面，不进入PDF。中文练习题目与答案保留原文。

没有实际作答记录时显示“暂无数据 / No data”，不会补造历史成绩。

## 数据接入

目前旧 zx_attempts 表没有云端记录，已有练习保存在浏览器。新版本从启用后的“开始练习”和“完整交卷”采集记录，后台按私有题库重新批改客观题。13份课程页面、145套练习已建立题目映射。错题重练不重复计入月报完成率；家长报告不显示造句自评；答题正确率只统计系统批改题目。

按新加坡时区归月。完成率分母为当月开始或提交的不同练习套数；分子为月内完成的不同套数。每套取月内最近一次完整提交。没有布置月度任务的功能，本版不把课程总题数当作月度任务。

家长报告不显示错题摘录，而是最多3项单元/知识点进步重点、实际表现及中英双语练习建议。每个单元至少记录5道客观题且至少错2道才生成建议；数据不足时不判断未掌握。建议使用固定规则，不调用AI。错题明细仅管理员网页查看，最多100道；统计包含全部记录。

历史报告保存当时的统计快照及双语评语。打开历史月份保留原快照，点击“刷新实际统计”后再保存才更新历史报告。

同步失败时给出提示并保留当前页重试队列，关闭页面前警告；不把同步失败的练习伪装成已上传。当前页关闭或崩溃后不会从旧浏览器成绩猜测作答日期。

## 安全和已有登录

- 不修改 backend/index.ts、现有登录表单处理或PIN哈希逻辑，不变更4个学生账号及课程授权。
- 新增独立 zhixu-reports 服务；管理员 JWT 由 Auth 服务验证，随后检查当前启用中的 admin 角色。
- 学生仅能凭现有受限会话记录自己的已授权课程，不能读取其他学生或管理员报告。
- 对题库、作答和报告开启RLS，内部RPC只授予service_role；客户端不含服务密钥。
- 新增练习记录和报告表，不覆盖原表或旧数据。
- PDF库随网站固定版本保存（html2canvas 1.4.1、jsPDF 3.0.3，含MIT许可证）；PDF在浏览器本机生成，不发送学生资料给第三方。
- PDF为高分辨率图像版，适合查看和打印，不提供可搜索文字层。

## 已验证

九组本地测试通过：原登录流程、课程权限、PIN哈希、原管理页面、全部13份课程初始化、完整作答采集、服务端批改与月报权限/时区/快照/中英文评语、报告界面的暂无数据及失败隔离。

已在浏览器实际点击导出，确认下载PDF为一页A4，并渲染检查中文和英文排版。预览使用虚构示例学生及无数据状态，未写入真实学生报告。

## 确认后部署

1. 再检查 GitHub main 和数据库最新状态，不覆盖他人的新增内容。
2. 应用 backend/report-schema.sql，新增两张私有表、月报表及专用服务端函数。
3. 私有题库从 backend/report-catalog.json 按课程分批导入 exercise_catalog；此文件不得提交公开仓库。
4. 对比当前课程正文与原始 course-content.json 的校验值，仅当一致时替换为 report-content.json 的采集版本；不改变题目、答案、登录和授权逻辑。更新后校验13份正文。
5. 部署 zhixu-reports，入口 reports.ts，依赖 security.ts，显式 import_map_path='deno.json'；verify_jwt=false，因为学生使用自有受限会话，函数内分别验证学生会话和管理员JWT。
6. 发布新增报告页、PDF库、成绩同步脚本，以及 portal.html 内的新入口。不发布私有JSON、真实学生资料或凭据。
7. 验证匿名/学生无法读取管理员月报；用5号测试账号做明确标记的真实练习，不伪造或混入其他学生记录；验证双语评语保存和PDF。测试记录是否保留先问用户，不擅自删除。
8. 运行安全检查。未使用的新表可保留默认拒绝；出现故障先停止发布新入口，保留原登录及课程站。

本版不导入任何演示成绩；正式统计从启用后的真实练习记录开始。

家长报告固定为四项：本月学习概况、值得肯定的表现、进步重点与建议、双语教师评语。肯定表现要求至少5道已记录题目且正确率达到80%，只陈述已记录结果，不虚构成长趋势。
